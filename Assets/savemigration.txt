|###################################################################|
| SAVE MIGRATION — retired + renamed serialized fields              |
| (READ BY THE SAVE READER AT LOAD — this file IS the mechanism)    |
|###################################################################|
| The save reader (CvTaggedSaveFormatWrapper) PARSES this file once |
| at load and self-heals the stream against it, so a removed field  |
| is FULLY GONE from the object — no member, no read, no write, no  |
| per-object WRAPPER_SKIP_ELEMENT. This is deployed under Assets/    |
| so the runtime DLL can read it (gDLL->getModName + Assets\).      |
|                                                                   |
| Why full removal: a DELETED member that is still referenced       |
| anywhere is a COMPILE error (caught); an empty stub silently      |
| returns a wrong value (hidden). Gone > stubbed.                   |
|                                                                   |
| FORMAT (one entry per line; headers/comments/blank ignored):      |
|   CUT:    ClassName::m_field            (type note, optional)      |
|   RENAME: ClassName::m_old -> ClassName::m_new                     |
| The reader keys on the normalized "Class::field" name (the same   |
| NormalizeName the dictionary stores). A CUT tag is drained where  |
| it appears; a RENAME tag is matched against the new member. So    |
| old saves load clean and the format is NEVER save-breaking as     |
| long as the entry is listed here.                                 |
|                                                                   |
| ⛔ Still true: never leave a live WRAPPER_READ for a deleted tag  |
| that ISN'T listed here — an unlisted orphan DESYNCS the whole     |
| downstream read (proven 2026-07-02: gutted tech lists). List it.  |
